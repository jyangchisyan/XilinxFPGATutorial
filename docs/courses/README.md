# 用這個專案學習 FPGA

這套課程從已上板運作的 Nexys A7-100T 專案開始，帶你讀懂系統、修改韌體、寫出第一個 RTL 模組，再把自己的電路交給 CPU 控制。

若想跟著互動上課的步調，可改讀 [20 個逐步小單元](steps/README.md)：每節聚焦一個觀念，包含練習、可展開的解答與過關標準。原本六課保留作完整參考。

目前已確認 LED[0] 規律閃爍：MicroBlaze 從 BRAM 開機、DDR2 校準、前 4 KiB 記憶體讀寫與 AXI GPIO 輸出都已完成基本上板驗證。完整 DDR2 容量與長時間穩定性尚未驗證。

## 課程順序

| 課程 | 主題 | 完成後可以做什麼 |
| --- | --- | --- |
| [01：讀懂 FPGA 系統與開機流程](01-system-and-boot.md) | FPGA、MicroBlaze、BRAM、bitstream | 解釋 LED 閃爍背後的完整路徑 |
| [02：用 C 程式操作 GPIO](02-firmware-and-gpio.md) | MMIO、volatile、位址、韌體建置 | 改變 LED 模式並重新下載 |
| [03：第一個 Verilog 電路](03-verilog-counter.md) | 暫存器、時脈、重置、計數器 | 寫出不需要 CPU 執行延遲迴圈的閃爍電路 |
| [04：用模擬驗證電路](04-testbench-and-waveforms.md) | Testbench、波形、自動檢查 | 在上板前找出週期與重置錯誤 |
| [05：讓 CPU 控制自訂硬體](05-axi-and-custom-logic.md) | AXI、暫存器、GPIO 橋接 | 從 C 程式設定自己寫的計數器 |
| [06：DDR2、重置與時序](06-ddr-reset-and-timing.md) | MIG、時脈域、CDC、setup/hold | 追查系統未開機或時序失敗的原因 |

每課都有概念、專案對照、練習、預期結果與自我檢查。先完成驗收，再進入下一課。

## 準備與操作慣例

- 基礎需求：能閱讀簡單 C 程式，理解二進位與十六進位；Verilog 從第 03 課開始介紹。
- 工具沿用本專案的 Vivado／Vitis 2024.2、MicroBlaze GCC，以及 Nexys A7-100T board files。
- 所有 shell 指令都從專案根目錄執行。若工具不在 `/tools/Xilinx`，請依安裝位置修改路徑。
- 第 01 課只閱讀；第 02 課修改韌體；第 03、04 課在 `learning/` 下建立獨立練習。
- 第 05 課使用專案副本，避免覆蓋已驗證的系統。文件中的範例模組目前尚未加入原始 Block Design。
- `build/` 是產生檔目錄；`learning/` 是你自行建立的練習原始碼目錄。
- JTAG 下載只更新 FPGA 當次設定，斷電後需要重新下載。

課程檔案本身不會自動修改硬體或韌體。程式區塊中標示的檔案，要在進行該練習時自行建立。

## 建議留下的學習紀錄

每次練習記下「預測 → 修改 → 結果 → 解釋」，例如：

```text
課程：02
預測：只把 LED 亮燈延遲減半，亮燈時間會縮短，暗燈時間不變。
修改：第一個 delay(4000000u) 改成 delay(2000000u)。
結果：……
解釋：……
```

不要只記錄「成功」。寫出哪個現象支持你的判斷，以及哪些部分還沒有驗證。

## 已知驗證範圍

原專案綜合、實作與指定時序約束已通過。包含 CPU／DDR2 的系統模擬曾完成編譯與 elaboration，但受管環境的 XSim 啟動異常，尚無完整系統模擬執行通過的結果。

後續課程中，獨立 `blink_counter` 的 testbench 已在主機終端機通過；刻意改錯時在 cycle 3 失敗，還原後再次通過。這項結果只涵蓋小模組，與完整系統模擬分開記錄。新頂層或自訂硬體仍需各自驗證。

硬體規格、原專案建置指令與警告紀錄見 [專案 README](../../README.md)。
